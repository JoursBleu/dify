Dify Windows 完整安装器
版本：Dify 1.17.1 / 安装器 1.0.8 / AMDGPUCloud 插件 0.0.8
插件与本地集成作者：Letian Kang
联系邮箱：Letian.Kang@amd.com

这是真正部署并启动 Dify 平台的 EXE，不是只有一个模型插件。
安装器已内嵌 Dify 官方 Docker 部署资产、Compose 运行器、许可证和 AMDGPUCloud 标准插件包。
首次安装需要联网下载 Dify API/Web、PostgreSQL、Redis、Weaviate、Sandbox、Agent 等运行镜像。
本版为联网安装器，不声称在无 Docker/WSL 的全新 Windows 上完全离线安装。

前提：Windows 10/11 x64、已启用 WSL2、WSL 内可用 Docker Engine 或 Docker Desktop WSL 集成。
完整本地栈建议至少给 WSL/Docker 4 核、8 GiB 内存和 20 GiB Linux 文件系统自由空间。
若前置依赖缺失，界面会指出原因并提供官方说明，不静默修改系统、接受 Docker 许可或重启电脑。
现有 WSL Docker Engine 可直接复用，无须额外安装 Docker Desktop。
Docker Desktop 在大型企业商业使用时可能需要订阅，请按官方许可核对。

关闭之前的旧安装器，双击 Dify-Setup-1.17.1-Windows-x64-1.0.8.exe：
1. 选择已有 WSL2 发行版，默认本机端口 18080。
2. 阅读 Dify 许可证，仅用于自己的单工作区，不移除 Dify 标识或版权。
3. 点击“安装并启动 Dify”；首次镜像下载需要数分钟，视网络而定。
4. 就绪后自动打开 http://127.0.0.1:18080/install，自行创建管理员账号。
5. 桌面与开始菜单会建立启动、停止和打开网页入口。
若公司浏览器代理影响localhost访问，将localhost/127.0.0.1加入代理例外；安装器自检不走代理。

AMDGPUCloud 原生模型提供方：
1. 打开Dify的“集成”，或点击安装器通用“插件管理”（http://127.0.0.1:所选端口/integrations）。
2. 使用Dify“安装→从本地文件”导入Downloads里的AMDGPUCloud-0.0.8.difypkg。
	安装器内嵌的同一插件位于payload/plugins/amdgpucloud.difypkg。
3. 在“集成→模型提供方→AMDGPUCloud”中配置自己的rc-* Key。
发布者letian-kang，插件名和Provider名amdgpucloud，显示名称AMDGPUCloud。
插件ID为letian-kang/amdgpucloud；完整供应商名letian-kang/amdgpucloud/amdgpucloud。
个人publisher与正式Marketplace账号归属批准不同，不宣称官方签名或上架。
获取Key：https://developer.amd.com.cn/radeon/modelapis（手动获取，不复制Cherry的登录来源参数）。
固定API：https://developer.amd.com.cn/radeon/api/v1；模型请求仍携带X-Source: dify。
插件尚未 Marketplace 签名；本地 Dify 默认验证插件签名。
只有你明确勾选“允许未签名开发插件（仅此新建本地实例）”才会在新实例放开该校验。
该选项是实例级而非单包白名单，不会修改其他 Dify 生产服务。
真实公网模型和业务路径仍需用户自己的测试 Key 验证，不内置任何 API Key。

完整 Dify 的代码/Workflow/RAG/Agent 功能保持官方组件；模型提供方的能力和计费独立。
AMDGPUCloud 本版不提供 Embedding/OCR/JSON Schema/并行工具，不能用聊天模型代替知识库向量模型。

安全与卸载：
所有实例服务密钥首次安装随机生成并以0600权限保存，不显示到日志，不写入EXE。
关闭窗口不等于停止服务；需要在界面点“停止 Dify”。
恢复从桌面入口启动即可；不默认添加开机计划任务。
此 EXE 尚未商业代码签名，不能将其宣称为 AMD 或 Dify 官方签名发行包。
先停止本实例并备份 WSL 数据，再人工决定是否删除；不提供一键删除数据按钮。
